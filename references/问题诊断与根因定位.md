# Diagnosis before retry

## Root-cause tree

```text
Incorrect or incomplete listing
├─ Environment: browser route, login, account, market, timeout
├─ Evidence: missed gallery/detail/spec/lazy image or stale page snapshot
├─ Identity: wrong variant, shared image treated as exact, mixed-model scene
├─ Asset state: URL duplicate, visual duplicate, weak OCR, corrupt download
├─ Handoff drift: renamed path stale, generated image not substituted, order mismatch
└─ Commit: upload incomplete, platform reordered images, write succeeded without readback
```

## Diagnostic protocol

1. Stop repeating the failing action.
2. Record the exact phase, expected observable result, actual observable result, error class, and whether the step is idempotent.
3. Inspect the nearest authoritative state: browser tab/DOM, upload thumbnails, local hashes, manifest counts, final order, API response, or record readback.
4. Classify the cause before changing anything.
5. Apply the smallest scoped correction and rerun only dependent gates.

## 持续处理闭环

仅在执行中出现真实异常时使用。请求若仅为流程维护，只改维护源和隔离测试，不恢复商品对话、生成图片、运行生产校验或写外部业务系统。

1. **锁住原目标**：区分用户明确要求（如修复指定译图、测试翻译生成）与可选图片。不能失败后把必需项改成可选，再靠减少序列宣告完成。
2. **记下可观察事实**：失败步骤、预期／实际、工具返回、文件版本；根因未确认就写假设。每个问题一个记录，不记录所有正常步骤。
3. **区分故障层次**：工具超时不等于上传失败；哈希不同不等于视觉错误；分辨率变化不等于商品参数变了。先确认实际处理对象。
4. **执行最小修复**：在已有授权范围内直接推进。根据单张缺陷修订替换表、选择准确原图、调整编辑方式或修复文件绑定；不反复发送相同请求。
5. **复测原失败步骤**：上传修复要看到正确附件；译图修复要复核实际下载文件；导出修复要对照源模块确认没有漏段；回填要读回一致。语法检查或工具成功不等于原问题修好。
6. **继续下一项**：验证恢复后继续原目标，不等用户再说“继续”。有新问题就回第 2 步，保留成功产物；“已定位”不是结束条件。
7. **结束前核对**：所有必需项有验证证据才完成。可选替代／删除必须证明不损失原目标，并保留原 FAIL；没有可执行路径才报告具体阻塞。临时绕过恢复了交付时，另列未根治的原因和后续动作。

同一无变化动作只做一次有依据的重试。纠正具体原因后属于新验证，不因“以前失败过一次”停止；每轮应带来新证据或可检验改变。权限、认证和内容策略拒绝不靠重复点击或改写请求规避。

## 常见错判及处置

| 现象 | 判定及动作 |
|---|---|
| 英文正确、商品语义保持，仅画布缩放／重编码 | 按 listing 输出要求核对清晰度、比例和完整性；未要求像素复刻时不单凭像素变化判视觉 FAIL。旧标准不适用时让产品对话重新判定，本地不改 PASS |
| 本地哈希与上传侧报告不同 | 核对实际上传文件、本地完整哈希和附件映射，必要时重传验证。平台转换只是待验证解释，不把 GPT 声称的哈希覆盖成本地真值 |
| 商品结构、颜色、数字、单位或译文真实改变 | 定位具体位置，修正提示／替换表，再生成和复核该图；不只记笼统“保真失败” |
| 减少图片后序列通过 | 仅说明当前序列可用。用户要求修复／翻译指定图或测试生成链路时任务仍未完成；可选图则记录缺失角色如何覆盖 |
| 导出漏掉 adjustment、fit 等模块 | 修复通用渲染器，测试任意已确认模块与内部字段隔离。源文案、载荷、目标读回逐层对照，不能只核对错误载荷写入一致 |
| 上传恢复但操作仍延迟 | 区分恢复路径已验证与延迟根因未解决；不影响当前必需交付可继续并明确残留。按当前工具文档和实际页面操作，不把本机补丁变成通用前置步骤 |

运行时补丁须有具体证据、必要授权并确认没有可用标准路径；记录适用版本、备份和回滚方式。升级后先检测是否仍需要。等待中的任务有界观察，同时推进独立工作。问题记录字段见 [数据契约](数据契约与文件规范.md)。

## Known failures and fixes

| Symptom | Likely cause | Diagnosis | Correct action |
|---|---|---|---|
| Browser call times out | UI/backend handshake exceeds caller timeout; operation may still be running | inspect live tab, URL, DOM, progress, and logs | raise the initial observation timeout; reuse the bound tab; never create duplicates until state is known |
| “No browser route” after prior tabs | stale IAB page/route state | list browser/tab bindings and compare the task session | close stale tabs or restart once, then create/bind one clean tab |
| Hidden file input does nothing | direct input click does not emit chooser | open the visible add-file menu and observe the menu state | arm the chooser, then click the visible “upload from computer” command |
| Adopted set lacks a necessary detail or dimension | relevant detail/specification position not checked | identify the concrete listing gap | inspect and download only candidates likely to fill that gap |
| Language detector says no German | filename/character-set heuristic or weak OCR | review the affected candidate in the product conversation | retain uncertainty until reviewed; do not expand to all page images |
| Correct translation exists but German publishes | publish order still points to source | compare `图片翻译清单.json` against authoritative sequence | replace the source path; then rerun path/language/order gates |
| Copy path disappears after renaming | copy and asset views changed independently | check every recommended path | regenerate `最终发布图片/` from one ordered manifest; do not hand-edit parallel copies |
| API write reports success but table is wrong | ignored field, wrong record, or stale view | read exact record and compare intended fields | mark complete only after readback equality |

## Retry boundaries

- Timeout: first observe, then retry the smallest idempotent operation once with a justified timeout.
- Translation: `5 → 3/2 → 1` handles batch failures. Quality failures need defect-specific correction; a failed single image is not automatically the end of the task.
- Authentication/permission/CAPTCHA: stop and request the required user action.
- Wrong variant or excluded image leakage: stop publication and re-run identity plus all downstream gates.
- Simple copy change: re-run copy, path, and payload checks only; do not re-download verified assets.
