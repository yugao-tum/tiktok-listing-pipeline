# 主图区全量采集，按信息价值交付

默认完整 listing 任务先抓取当前产品的整个主图轮播区，包括首张展示图和该轮播区的其余图片。范围止于这个产品图库，不包括推荐商品、评论、页头页尾、站点装饰，以及未发现信息缺口时的详情长图。主图不是只指轮播首张，也不表示图库中每张都属于目标 SKU。

## 固定范围与采集

新任务默认 `asset_collection_mode: gallery_all`，字段缺省时也按此模式验收。Shopify 脚本以商品专属 `images` 数据为边界，记录来源 URL、位置、变体标记及预期数量；数组可能包含其他变体的媒体，先完整采集再判断是否采用。若数据与页面实际轮播数量不符，核对目标变体切换、懒加载及视频项，不把未确定的图库说成已抓全。非 Shopify 站点需从实际产品图库取得同样清单，不把整页所有 `img` 当成主图。

```powershell
python -m pip install -r requirements.txt
python scripts/采集Shopify产品素材.py --product-dir "<工作区>/产品工作区/<产品编号>"
```

脚本默认抓取全主图区并按字节去重，相同文件可对应多个位置。已有文件哈希吻合就复用；失败保留位置及原因，再执行时只补失败文件。预期位置数、已下载位置数和唯一文件数不是同一个指标。发现列表为空或不完整时先定位，不自动退到详情区凑数。

`--positions 11 12` 仅用于明确的补图位置；`--discovery-only` 仅发现 URL；`--all-images` 仅用于另行要求的全素材归档。后两者和局部下载均不能冒充默认完整 listing 已采齐。旧任务续做使用原目录，不重新初始化；补齐主图范围和审计后重跑 QA，不能通过改成 `selected_only` 绕过缺图。只有用户明确只做局部阶段时才使用 `selected_only`，并在结果中说明未覆盖完整主图区。

## 选图与验收

1. **先固定购买信息。** 根据用户目的、目标变体和已确认商品事实记录 `image_plan.required_roles`，例如目标款外观、影响购买的核心功能、选型所需尺寸。它不是通用模板配额，不能先选 5 张，再倒推 5 个角色证明够用。未知参数不编造，不以没有图片为由把必需角色删掉。
2. **全主图区轻量初筛。** 去重后的每张主图在产品 GPT 对话中至少看一次；大图库使用 [编号总览](批量执行与提速.md)，默认每张 12 图、一次 3 张总览。原图精审／翻译仍每批最多 5 张。记录 adopt、exclude 或待确认及理由；上下文与哈希一致的旧结论可复用。看不清就看相应原图，未看过不能写成不合格或重复。
3. **只精审采用图和疑点。** 清晰的排除结论不重复展开审计。拟采用图确认变体、文字语言、混入、信息正确性和用途；初筛已完成充分判断时复用该详细记录，不强制再次上传。疑点只补相关原图或证据。
4. **保留有用差异，按缺口补图。** 正确且有新增购买信息或明显更清楚表达的图应保留，不追求最少张数。被排除为重复的图应指出由哪张图覆盖。主图区筛完后仍有必需信息缺口，才补详情／规格图。若有已核实的平台张数限制，选最有价值的组合并说明替代取舍，不能假定限制值。
5. **只翻译采用图。** 全量抓取不要求全部翻译。复用已按正确标准通过复核的现有译图，必要时修复具体问题；使用旧译图通过复核不等于测试了新的生图链路。
6. **用覆盖和逐图取舍解释结果。** 最终张数由有效内容、重复程度和明确发布约束共同决定。主图全部有处置、预先确定的必需角色由采用图支撑、所有采用图通过质量验收，才可说本次范围完成。

## 最小记录

不新增平行台账，继续使用现有文件：

- `图片资产清单.json.gallery_inventory`：`source`、`source_url`、`expected_count`、`discovered_count`、`downloaded_count`。所有主图位置在 `items` 中保留 `section: gallery` 和 `section_position`，下载失败也不删行。
- `GPT图片审计记录.json.gallery_screening`：每个唯一主图哈希一条 `{asset, sha256, decision, reason}`。最终 `decision` 为 `adopt` 或 `exclude`，必须与最终序列的原图来源一致；待确认项不能通过完成校验。
- 同文件 `items`：保持原有采用原图详细复核字段；未采用主图只需上述轻量记录，不强求全套详细字段。
- `文案底稿.json.image_plan.required_roles`：选图前固定的非空角色列表；同一审计文件 `final_sequence_review.role_coverage` 为 `{角色:[采用原图完整哈希]}`，译图对应原图哈希也计入覆盖。

这些字段只能检查完整性与绑定，不能自动证明看图结论或商业需求合理。自动报告分别列主图位置总数、下载位置数、唯一主图数、初筛数、采用主图来源数和补充来源数；飞书状态也使用同样口径。交付仍是固定 `上架交付/产品编号/`，只包含采用图片、一份文案和交付清单，不把全部源图复制进去。

对外不要只说“通过 14 项检查”或“采用 5 张”。应说明“主图区 N 个位置，下载 N、去重后 U 张且初筛 U；采用主图区 G 张、补充 D 张，最终 P 张，其中译图 T 张，未决问题 R 项”。下载、初筛、详细复核、采用和翻译分别计数。
