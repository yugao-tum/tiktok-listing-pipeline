# Agent 调度、模型与成本

## 调度目标与能力边界

目标是降低“得到合格上架结果”的总消耗，包括调用、等待、交接和返工，不能只看模型档位。优先复用已验证成果和既有脚本，不为显示并行而建立 Agent。

此前只有角色能力建议，未要求实际传入模型参数。以下是执行者调用现有 Agent 工具时的调度规则，不是独立后台调度服务，也不代表已经调用过这些模型。

- 每次任务开始检查当前工具提供的模型及其支持的思考等级，不假定公开版、API、Codex 和网页 ChatGPT 的名称、价格或参数相同。以下型号来自维护时可用的 Codex 工具，运行时列表优先；缺失时用当前可用的对应能力型号或沿用主会话，并说明实际选择。
- 当前主会话设置不能靠写提示词切换。已有主会话沿用设置；有明确需求且工具支持时才能指定子 Agent 的模型和思考等级。不要声称已切换却没有调用参数或返回证据。
- 启动子 Agent 仍需用户或适用上级指令允许，且有具体、独立、有并行收益的子任务。此表本身不扩大授权，也不要求维护流程时运行商品任务。
- Codex Agent 的模型与产品 ChatGPT 对话中的视觉／生图模型是两层设置。全部视觉判断仍在产品专属 GPT 浏览器对话内完成，不能为省成本转给本地轻量 Agent。

## 默认选择

| 工作 | 建议选择与思考等级 | 使用条件与边界 |
|---|---|---|
| 下载、哈希、去重、文件汇总、已有校验与载荷生成 | 既有脚本／工具，无额外 Agent | 确定性工作不另开模型；脚本失败才进入诊断 |
| 已提供资料中的字段提取、整理、固定格式转换 | `gpt-5.6-luna` / `low` | 仅在工作量足以抵消交接时委派；不能批准变体、商业断言或视觉结论 |
| 单产品证据整理、基于已确认事实写完整文案、明确原因的小修复 | `gpt-5.6-terra` / `medium` | 边界清楚且可独立验收；复杂矛盾交回主协调者 |
| 跨来源身份矛盾、复杂根因定位、关键验收裁决 | `gpt-6-astra` / `high` | 优先由已有 GPT-6 主协调者承担，避免再启动一个相同职责的 GPT-6；普通协调以 `medium` 为建议起点 |
| 多种根因仍有实质竞争解释，定向修复后仍失败 | `gpt-6-astra` / `xhigh` | 仅针对未解的最小问题临时升级；常规任务不默认 `max`／`ultra` |
| 浏览器操作、飞书写入和回读 | 复用现有唯一资源负责人 | 简单明确操作无需额外高思考 Agent；歧义先交协调者，外部写入仍受原授权和 QA 约束 |

型号是能力路由的起点，不是已测得的最低价组合。没有当前价格和实际计量时，只能报告采用了节省调用／返工的策略，不能宣称更便宜多少或把订阅额度百分比折算成美元。

## 持续分配与升降级

1. **开始与阶段交接时**：先看待办、已验证产物和依赖，合并重复工作。机械步骤走脚本；短小步骤由现有 Agent 顺手完成。只有可独立推进的工作才建立子任务，不为一个产品同时建立研究、素材、文案等多套长期 Agent。
2. **决定并发时**：总并发不超过当前槽位；通常主协调者加 1～2 个子 Agent 即可。只有三个产品确实可独立推进且没有共享瓶颈时，才考虑主协调者加 3 个子 Agent。浏览器和飞书各只有一个负责人；等待它们时可推进独立文案／证据工作，不能开更多 Agent 争用同一资源。
3. **每个子任务完成、验收失败或出现新证据时**：检查结果是否减少了未完成事项。通过就继续依赖任务，不再让其他模型重复完整审计；无收益则收缩或结束该子任务。已通过阶段不因换模型重新执行。
4. **失败先分因再升级**：事实缺失就补定向证据；登录、上传、网络、工具参数问题按诊断流程处理，增加思考等级不能代替修复工具问题。对推理或文案质量失败，给出具体差异后做一次定向纠正；仍失败或一开始就是高难矛盾，再交 GPT-6 `high`。避免轻量、中等、强模型逐层把同一任务全部重做。
5. **强模型解决后**：把结论、修复及验收证据交回常规步骤。下一项独立简单任务恢复脚本或低成本路由，不让临时高思考扩大到整轮任务。已运行 Agent 不支持切换时，完成当前问题后再分配下一任务，禁止为降档反复重建上下文。
6. **收尾时**：确认原目标和问题闭环，不用预算压力取消必需修复，也不因有剩余槽位追加选图、审图或商品。若用户提供硬预算，接近上限时保留检查点、明确剩余必需工作；不得把未完成标成完成。

## 实际调用与上下文

环境支持 `collaboration.spawn_agent` 时，委派一个已获准、边界明确的文案子任务可用：

```json
{
  "task_name": "product_copy",
  "fork_turns": "none",
  "model": "gpt-5.6-terra",
  "reasoning_effort": "medium",
  "message": "处理指定产品的文案子任务。读取给定任务与证据文件，仅修改被分配的文案路径；不做视觉判断或外部写入。保留所有已确认详情模块、排除内部待确认字段。返回产物路径、变更摘要、未解问题与验收依据。实际调用前补齐产品编号、文件绝对路径、目标变体和明确验收条件。"
}
```

示例不是可直接执行的商品任务。实际调用必须填入真实、最小充分上下文，不能把占位符交给子 Agent。工具不支持显式型号或等级时沿用配置，不伪造额外参数；遇到参数不支持先修参数，不把整个商品重复调度。

- 显式覆盖型号／等级时使用当前工具允许的上下文模式；此环境不能在 `fork_turns: all` 时覆盖它们，优先 `none` 加精简任务包，必要时仅带有限轮次。
- 子任务包包含原目标、产品／变体、证据与产物路径、允许写入范围、已确认结论、未解问题和验收标准。不要复制整段历史、原始大日志或无关图片；相关 Skill 约束需显式传递或给出读取路径。
- 只在真实委派或配置变化时，在现有 `执行状态.json` 的可选 `agent_dispatches` 中追加简短记录：子任务、Agent 标识、实际模型与等级（不可见则 unknown）、选择原因、结果与产物路径。结束时补充重试数和可用的实际耗时／用量；不可见数据留空，不猜测。
- 复用适合的现有子 Agent，使用摘要和文件路径交接，完成后等事件通知而非频繁轮询。下一轮按首次验收是否通过、返工次数和实际耗时调整路由；轻量路线省了单次调用却增加总返工时，提升同类任务的起始档位。

## 资源职责

协调者维护批次状态和验收；产品负责人仅写自己的证据／素材／文案目录；浏览器负责人维护产品 GPT 对话、图片审计记录和译图下载；飞书负责人只消费已批准载荷并记录回读。复用角色时仍保持每个可写目录及共享资源同一时刻只有一个写入者。

## Round contract

- One round contains one to three product leases.
- Each lease fixes `round_id`, `product_id`, `product_url`, variant ID/SKU, owner, artifact version, and current phase.
- Product work is isolated under `产品工作区/<product_id>/`; no agent may copy identity, facts, or media from another product.
- Shared resources are templates, schemas, scripts, and read-only field definitions only.
- The browser owner processes the three products in a deterministic order and keeps one ChatGPT conversation per product. Every image-based judgment must originate in that conversation and be mapped back by filename plus SHA-256.
- The Feishu writer receives only products with a matching QA artifact hash and commit token.

## Prepare/commit barrier

Prepare agents may create evidence, assets, copy, translation plans, and payload previews. They cannot perform external writes.

The coordinator issues `ready_to_commit` only when:

- exact variant and exclusions are confirmed;
- the product gallery is fully captured and screened with hash-bound dispositions, adopted originals and translation sources have detailed GPT reviews, and the final sequence covers required purchase-information roles; unused non-gallery inventory is outside the release gate;
- all recommended paths exist and no banned asset is present;
- original-language assets are replaced in the publish sequence;
- every adopted translated output has a passed GPT fidelity and residual-language review;
- copy values are supported or explicitly TBC;
- final image titles, ranks, and files agree;
- QA passes.

The writer records the request summary and performs readback. A failed product stays isolated; it does not block the other two unless the failure affects a shared schema, browser session, or account state.

## Reporting

For each product report only: `committed`, `ready_to_commit`, `ready_to_publish`, `needs_rework`, `blocked`, or `failed_isolated`; include the evidence-based cause and the next safe action.
