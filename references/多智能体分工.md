# Three-product agent orchestration

## Default roles

| Role | Model / reasoning | Scope | Writes |
|---|---|---|---|
| Coordinator and QA gate | high-reliability model, high | all three products, conflicts, release gates | round state and final approval only |
| Product researcher ×3 | balanced model, medium/high | one product each; identity, evidence, source facts | own product evidence only |
| Asset worker ×3 | fast model, medium | download, hash, dimensions, manifests | own product asset directory only |
| Copy worker ×3 | balanced model, medium/high | titles, bullets, detail modules, image subtitles | own product copy directory only |
| Browser owner ×1 | reliable interactive model, medium/high | all ChatGPT conversations and external UI | browser state and downloaded localization outputs |
| Feishu writer ×1 | high-reliability model, medium | approved payloads only | Base schema/records and receipt |

Reuse agents when slots are limited. A product agent may do research, then assets, then copy, but never operates browser or Feishu concurrently with another owner.

## Round contract

- One round contains one to three product leases.
- Each lease fixes `round_id`, `product_id`, `product_url`, variant ID/SKU, owner, artifact version, and current phase.
- Product work is isolated under `产品工作区/<product_id>/`; no agent may copy identity, facts, or media from another product.
- Shared resources are templates, schemas, scripts, and read-only field definitions only.
- The browser owner processes the three products in a deterministic order and keeps one ChatGPT conversation per product.
- The Feishu writer receives only products with a matching QA artifact hash and commit token.

## Prepare/commit barrier

Prepare agents may create evidence, assets, copy, translation plans, and payload previews. They cannot perform external writes.

The coordinator issues `ready_to_commit` only when:

- exact variant and exclusions are confirmed;
- all recommended paths exist and no banned asset is present;
- original-language assets are replaced in the publish sequence;
- copy values are supported or explicitly TBC;
- final image titles, ranks, and files agree;
- QA passes.

The writer records the request summary and performs readback. A failed product stays isolated; it does not block the other two unless the failure affects a shared schema, browser session, or account state.

## Reporting

For each product report only: `committed`, `ready_to_commit`, `ready_to_publish`, `needs_rework`, `blocked`, or `failed_isolated`; include the evidence-based cause and the next safe action.
