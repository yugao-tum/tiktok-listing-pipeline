# Pipeline and optimization boundary

## Purpose

The default output is one exact-variant local listing package with a single authoritative publish sequence, recoverable evidence, localized images and QA status. Feishu writeback and TikTok publication are separate optional destinations, performed only when requested and authorized.

## Stage outputs

Default to whole product-gallery capture → deduplicate bytes → screen all unique gallery images → detail-review adopted/uncertain candidates → translate adopted images → final-sequence QA. Required purchase-information roles are fixed before selection and mapped to adopted sources. Only add detail/specification images for identified gaps; website-wide archiving is a separate task. See [主图采集与选图规范](主图采集与选图规范.md).

“Enough for listing” never cancels an explicit repair, translation or stage-test requirement. A real failure enters the diagnosis/correction/retest loop before proceeding; optional exclusion and temporary recovery are separate outcomes, not repaired defects. Use the existing diagnostics reference rather than adding a full audit for each product.

1. **Intake** — `产品任务.json`, exact variant, exclusions, target language, Base mapping.
2. **Evidence** — append-only `证据记录.jsonl`; raw page facts remain distinct from inference.
3. **Assets** — `图片资产清单.json/csv`, immutable whole-gallery `原始图片/`, per-position source and variant scope plus `gallery_inventory`; non-gallery assets may remain metadata-only.
4. **GPT image audit** — `图片审计/GPT图片审计记录.json`, per-product conversation URL, all-gallery `gallery_screening`, detailed adopted-source judgments, translation reviews and final role coverage.
5. **Copy** — `文案/文案底稿.json` and `文案/文案底稿.md`, claims linked to evidence, unsupported fields marked TBC.
6. **Localization** — `图片翻译计划.json`, per-attempt events, `英文翻译图片/图片翻译清单.json`.
7. **Publish view** — versioned `最终发布图片/<sequence_hash>/` plus `最终发布图片/当前发布清单.json`; names follow final order and meaningful Chinese image subtitles.
8. **QA** — `质量检查/质量检查报告.json` for copy/evidence review (including `draft_sha256`), and script-generated `质量检查/自动校验报告.json` for mechanical validation. Neither substitutes for the other.
9. **Folder delivery** — `汇总上架交付文件.py` rechecks QA and writes only current adopted images, one complete copy file and a manifest to stable `上架交付/<product_id>/`. Reuse unchanged files; no product archive. See [交付文件夹规范](交付文件夹规范.md).
10. **Optional commit** — prepared Base payload, artifact-bound commit-token sidecar, writer receipt, and readback comparison.

When issues occurred, carry `质量检查/问题处理记录.json` with closure evidence. Before marking the requested task complete, report which stages actually ran: e.g. using reviewed originals can complete a listing but does not exercise image generation. A reusable script defect fixed in a task-specific adapter should be promoted to the maintained implementation with a focused regression test.

## Scriptable versus agent/browser work

Script these deterministic stages:

- validate job identity and initialize three isolated workspaces;
- normalize URLs, download, decode, hash, strict-deduplicate, and reconcile counts;
- create/revise translation batches and idempotency keys;
- verify file existence, hashes, ranks, exclusions, and translated-output substitution;
- copy final assets and rename from ordered subtitles;
- render text modules and construct the Feishu batch-update payload;
- compare Base readback with intended values.

Keep these as non-image agent judgments:

- commercial copy, evidence boundaries, and TBC decisions;
- structured product-data interpretation that does not require looking at an image.

Keep these under the single browser owner:

- all visual comparison and judgment: product/variant match, duplicate grouping, text/language review, mixed-model rejection, image role, commercial suitability, final order, and translated-image fidelity;
- ChatGPT project conversation creation, audit prompts, uploads, generation, review, and result download;
- TikTok Seller Center entry/upload/publish and actual UI-order readback when authorized.

The browser owner writes the GPT conclusions to `图片审计/GPT图片审计记录.json`. Other agents may validate filenames, hashes, coverage, and required fields, but may not replace or silently reinterpret the visual conclusions.

Keep Feishu writes under one writer. Other agents may only prepare payloads.

## Image throughput

For large galleries and repeated rounds, follow [批量执行与提速](批量执行与提速.md): numbered overview screening, context-bound delta work and compact browser exchanges. First-pass overview sheets are separate from original-image detailed review and translation batching; never use thumbnail review as translation approval.

Default translation request size is five confirmed images. If the batch fails:

1. Preserve outputs already proven successful.
2. Split only failed items into `3+2`.
3. Split a failed subgroup into single images.
4. A remaining single failure from a larger batch gets one single-image attempt; a deterministic failure of that attempt stops and records the cause.

Network/temporary service failures may use bounded backoff. Content rejection, corrupt source files, wrong parameters, login expiry, CAPTCHA, and permission errors require diagnosis or user action, not repeated regeneration.

## Renaming rule

Download names are evidence names and remain unchanged. Publish names are created only after final ordering:

```text
01_主图_深灰带脚托.jpg
02_核心卖点_可伸缩脚托.jpg
03_功能图_90至150度后仰_EN.png
```

Use the approved image subtitle, sanitize Windows-invalid characters, keep the extension, and append a stable hash only on a genuine collision. Translation outputs replace source-language images in the publish sequence; they are not appended as extra images.

## Completion

Local completion requires full gallery capture and first-pass dispositions, required-role coverage, detailed adopted-source/translation review, both QA checks and a verified current delivery folder. Unused non-gallery assets need no processing. External writes and readback are required only when requested. `committed` means Feishu readback matched; TikTok `published` needs platform evidence.

Do not trust an old QA label by itself. Immediately before payload construction, recheck the final renamed files and compare the current artifact hash with `质量检查/自动校验报告.json` and `执行状态.json`. Any missing or changed file returns the product to QA instead of producing a stale commit package.
