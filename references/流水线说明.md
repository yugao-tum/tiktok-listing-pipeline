# Pipeline and optimization boundary

## Purpose

The output is not a collection of plausible copy and downloaded files. It is one exact-variant listing package with a single authoritative publish sequence, recoverable evidence, localized images, QA status, and verified Feishu writeback.

## Stage outputs

1. **Intake** — `产品任务.json`, exact variant, exclusions, target language, Base mapping.
2. **Evidence** — append-only `证据记录.jsonl`; raw page facts remain distinct from inference.
3. **Assets** — `图片资产清单.json/csv`, immutable `原始图片/`, counts and variant scope.
4. **Copy** — `文案/文案底稿.json` and `文案/文案底稿.md`, claims linked to evidence, unsupported fields marked TBC.
5. **Localization** — `图片翻译计划.json`, per-attempt events, `英文翻译图片/图片翻译清单.json`.
6. **Publish view** — versioned `最终发布图片/<sequence_hash>/` plus `最终发布图片/当前发布清单.json`; names follow final order and meaningful Chinese image subtitles.
7. **QA** — `质量检查/质量检查报告.json/md`, explicit blocking and non-blocking findings.
8. **Commit** — prepared Base payload, artifact-bound commit-token sidecar, writer receipt, and readback comparison.

## Scriptable versus agent/browser work

Script these deterministic stages:

- validate job identity and initialize three isolated workspaces;
- normalize URLs, download, decode, hash, strict-deduplicate, and reconcile counts;
- create/revise translation batches and idempotency keys;
- verify file existence, hashes, ranks, exclusions, and translated-output substitution;
- copy final assets and rename from ordered subtitles;
- render text modules and construct the Feishu batch-update payload;
- compare Base readback with intended values.

Keep these as agent judgments:

- exact-variant interpretation when a page mixes shared and variant-bound images;
- effective visual deduplication and mixed-model scene rejection;
- OCR/language review when confidence is weak;
- commercial copy, evidence boundaries, and TBC decisions;
- generated-image visual fidelity and residual-language review.

Keep these under the single browser owner:

- ChatGPT project conversation creation, upload, generation, and result download;
- TikTok Seller Center entry/upload/publish and actual UI-order readback when authorized.

Keep Feishu writes under one writer. Other agents may only prepare payloads.

## Image throughput

Default translation request size is five confirmed images. If the batch fails:

1. Preserve outputs already proven successful.
2. Split only failed items into `3+2`.
3. Split a failed subgroup into single images.
4. After one single-image retry for a deterministic failure, stop and record the cause.

Network/temporary service failures may use bounded backoff. Content rejection, corrupt source files, wrong parameters, login expiry, CAPTCHA, and permission errors require diagnosis or user action, not repeated regeneration.

## Renaming rule

Download names are evidence names and remain unchanged. Publish names are created only after final ordering:

```text
01_主图_深灰带脚托.jpg
02_核心卖点_可伸缩脚托.jpg
03_功能图_90至150度后仰_EN.png
```

Use the approved image subtitle, sanitize Windows-invalid characters, keep the extension, and append a stable hash only on a genuine collision. Translation outputs replace source-language images in the publish sequence; they are not appended as extra images.

## Completion

Local completion requires a passing validation report. Workflow completion additionally requires the external destination to be written and read back. If TikTok publishing is outside the current authorization, report `ready_to_publish`, not `published`.

Do not trust an old QA label by itself. Immediately before payload construction, recheck the final renamed files and compare the current artifact hash with `质量检查/自动校验报告.json` and `执行状态.json`. Any missing or changed file returns the product to QA instead of producing a stale commit package.
