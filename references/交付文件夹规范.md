# 上架交付文件夹

完整上架任务结束时交付一个可直接打开、复制或上传的文件夹，默认不生成商品压缩包。流程维护任务仅修改规则和脚本，不整理真实商品文件。

```text
上架交付/
  产品编号/
    上架文案.md
    图片/
      01_产品主图.png
      02_功能细节.png
    交付清单.json
```

`上架文案.md` 统一包含中文标题、英文标题、英文卖点、完整英文详情和相对图片顺序。图片目录包含全部采用原图和全部采用译图：不需翻译的合格原图同样按顺序和中文内容名命名并放入。译图替换对应外语原图，不把两者同时交付。交付清单 `image_counts` 分别记录 original、translated 和 total，并核对文件。未确认参数、内部证据和禁用说明不进入消费者文案。额外文件仅在用户确实需要时提供。

两项 QA 通过后执行，参数只包含本次指定的 1～3 个产品：

```powershell
python scripts/汇总上架交付文件.py --product-dir "<工作区>/产品工作区/<产品编号>"
```

默认输出到同一工作区的 `上架交付/`；用户指定位置时用 `--output-root "<交付目录>"`。多产品可在 `--product-dir` 后连续提供目录。交付目录必须与商品证据目录分开。

去重与更新规则：

- 固定使用产品编号目录，不按日期、轮次或“最终版”另建副本；相同哈希的文件原地复用，不重复写入。
- 每个产品只输出一份文案，不同时制造内容重复的 TXT、Markdown、JSON 等消费者副本。交付清单仅记录产品、验收快照和文件哈希，不重复文案或图片内容。
- 更新仅替换脚本曾生成且未被用户修改的文件；淘汰文件也仅在旧清单登记且哈希仍一致时删除。用户新增文件保留，用户修改引发冲突时保留并报错。
- 完全相同字节的图片重复进入最终序列时退回排序复核，不擅自改动已批准顺序。相似图片是否重复仍由产品 GPT 对话判断。
- 工作区保留原始证据和验收时的发布快照，交付目录另存当前采用文件，因此仍有必要的工作副本；不使用依赖原工作区的快捷方式、符号链接或硬链接。去重重点是同一交付目录只留当前一套，重复执行不增生副本，不承诺全磁盘只有一个文件。
- 历史工作区版本用于溯源，不主动清理真实任务证据；已有商品 ZIP 不自动删除，也不继续更新。Skill 安装发行包与商品交付是不同用途。

脚本在写入前重新验证当前文案、QA、图片及快照；完成后按哈希读回交付文件。已提交飞书的产品可只读重新导出，执行状态不退回、不会再次外部写入。只有交付命令成功才可报告文件夹已更新；失败时不得把先前目录当成本次已完成。没有外部写入要求时，到交付文件夹即完成。
