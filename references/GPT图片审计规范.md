# GPT 内置浏览器图片审计规范

## 唯一审计入口

所有需要看图后作出判断的任务，都必须在 GPT 内置浏览器中的产品专属 ChatGPT 对话完成。每个产品只使用一个对话，审计、翻译和译图复核都在该对话中连续进行，避免上下文和产品身份漂移。

本地 Agent 或脚本只能提供文件名、SHA-256、尺寸、下载来源、结构化商品数据和候选提示；不能自行决定图片是否属于目标变体、是否重复、是否含需翻译文字、是否适合发布或译图是否合格。

## 审计流程

默认范围是 listing 候选图，验收范围是最终采用图及译图对应原图。先按主图、必要卖点、细节／尺寸等信息需要小批选图；合格图片足够支撑上架就停止。未采用图不要求下载、审计、翻译或逐张解释排除原因。历史全量下载也不扩大本次审计范围。

1. 先在对话中固定产品 ID、目标变体、SKU、选项和排除变体。
2. 只上传本轮候选图，严格相同字节不用重复上传。每张同时提供文件名、完整 SHA-256 和页面位置；一次至多 5 张。不合格时再补候选，不扫描剩余全部图片。
3. 要求 GPT 对每张图返回：
   - 是否为目标产品及目标变体；
   - 是否与其他图片视觉重复；
   - 是否混入其他型号或变体；
   - 是否存在可读文字及其语言；
   - 建议用途、中文小标题、是否进入发布序列及原因。
4. 对不确定结论使用 `uncertain_requires_review`，补充更清晰图片或页面证据后继续同一对话；不能由本地推断替代。
5. 仅翻译已采用且确认需要翻译的图片，仍按 `5 → 3+2 → 1` 退级。已成功图片不重复生成。
6. 先下载生成文件到待复核位置并计算完整哈希，再将实际本地文件与原图成对提交到同一对话，逐张检查文字是否完整英文、产品/颜色/图标/尺寸/数字是否保持、布局是否明显变形。只有通过的输出可进入发布序列。
7. 最终排序确定后，把整套序列及其文件名再次交给同一对话审核，记录序列哈希和结论。

## 落盘要求

默认按 listing 可用性验收：正确商品／变体、准确可读英文、数字与单位准确、无明显失真。此处“尺寸不变”指商品尺寸数值不被改写；画布像素宽高只有用户或目标平台明确要求时才固定。合理缩放、抗锯齿与编码差异不自动造成视觉 FAIL，不能把“仅替换文字”升级为非文字区逐像素完全一致。

文件哈希标识字节，不证明视觉质量。视觉结论与文件绑定分别判断；绑定不明时先核对实际文件再采用。哈希由本地工具计算；GPT 没有工具读取字节时只能原样回传，不得假称重新计算。真实结构／颜色／信息改变仍 FAIL。

旧判定基于不适用标准时保留原记录，让产品对话按正确标准复核实际文件；流程维护本身不能把旧 FAIL 改为 PASS。已选图失败默认进入诊断和修复，不自动删除来绕过原交付要求。

浏览器拥有者把候选图结论写入 `图片审计/GPT图片审计记录.json`。最终采用图及对应原图必须有对话 URL、完整 SHA-256、逐图结论、必要的译图复核和序列批准。未采用图可无记录；未使用的失败译图可保留历史，不影响当前序列验收。

脚本只校验四件事：记录是否齐全、SHA-256 是否匹配、发布序列是否仍是被审核版本、是否存在未解决或未通过项。对话超时不等于审计失败；先观察实际对话、上传缩略图和生成状态，再决定是否重试。

直接使用 [分阶段提示词.md](分阶段提示词.md) 中本阶段的模板及字段枚举。哈希由本地计算，GPT 原样回传，不要求模型计算文件哈希。历史 `质量检查/人工视觉审查.json` 不能代替本规范的记录；由 GIF 等派生的新文件也必须按新哈希在产品对话中审计，不能自动继承原图结论。
