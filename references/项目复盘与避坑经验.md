# Pilot retrospective

## What the earlier listing chat got right

- It noticed that one product page contained both footrest and no-footrest options and warned that footrest claims must remain SKU-specific.
- It produced a useful commercial order: identity/scene, core differentiators, ergonomics, details, mobility, dimensions.
- It identified the two German infographics and proposed correct English replacements.

## What remained incomplete or misleading

- The earlier count treated 22 image placements and 19 unique images as final, but it did not reconcile gallery, detail, specification, lazy-loaded, duplicate, and excluded-variant sources separately.
- Its “directly usable” set included a no-footrest image from the wrong variant.
- Image generation failed, so the result was only an extraction plan; no localized files were delivered.
- It had no local manifest, immutable sources, final publish view, QA gate, or destination readback.

## What the pilot run changed

- Official inventory and publishable inventory were separated. One wrong-variant image was excluded rather than counted as usable.
- A missing specification image and two mixed-model near-duplicate office scenes were found during independent QA.
- One German infographic was initially mislabeled by metadata inspection; direct visual review corrected it.
- Download renumbering invalidated five copy paths. The new design derives every downstream path from one ordered manifest.
- Both English images were generated and downloaded, but QA caught that the recommended sequence still referenced the German sources. Generated outputs now replace sources atomically in the publish sequence.
- The final pilot used 13 publish images, including the two localized outputs, and passed all blocking gates before Feishu writeback.

## Browser diagnosis learned from the run

- A 30-second caller timeout was shorter than the first usable in-app browser binding on that host. The tab and page could already exist even when the call reported timeout.
- Repeated tab creation made the route state less clear. A single clean restart, one bound tab, and a longer initial observation resolved the control path.
- Directly clicking ChatGPT's hidden file input did not emit a file chooser. Opening the visible add-file menu and then choosing upload-from-computer did.

The resulting rule is: after a timeout, inspect the actual tab, URL, DOM/progress, upload thumbnails, or local artifacts before retrying. Change only the failed layer.

## Pipeline changes derived from evidence

1. Three isolated products per round, not an unbounded queue.
2. Five translation images per request, degrading failed subsets to 3/2 and then 1.
3. Source images remain immutable; final images are copied and renamed from rank plus subtitle.
4. One authoritative publish order feeds filenames, copy, ChatGPT output substitution, TikTok upload, and Feishu text.
5. One browser owner and one Feishu writer prevent concurrent state drift.
6. Local PASS and external readback are separate completion gates.
