# TikTok Shop 商品上架流水线

这是一个面向 Shopify／品牌商品页到 TikTok Shop 商品资料的 Codex Skill。它把产品证据、英文文案、图片翻译、最终排序、质量检查和飞书录入组织为可恢复、可验证的流水线。

## 核心能力

- 每轮处理 1～3 个产品，产品目录和 ChatGPT 对话相互隔离。
- 默认按上架需要选图，审候选图，只翻译采用图；素材足够且正确就停止，不要求整页下载或全量审阅。
- 所有图片审计和视觉分析统一在 GPT 内置浏览器的产品专属 ChatGPT 对话中完成；本地脚本只校验文件、哈希和覆盖率。
- 图片翻译默认每批 5 张；失败项降级为 3+2，再降为单张。
- 最终图片按发布顺序和中文小标题命名。
- 任务完成后汇总到一个固定的 `上架交付/` 文件夹：按产品分目录，只有采用图片、一份完整文案和交付清单；默认不生成商品 ZIP，重复执行复用文件。见 [交付文件夹规范](references/交付文件夹规范.md)。
- 区分目标变体、共享图片、其他变体和未知归属，避免混入错误 SKU 素材。
- 遇到超时或异常时先检查实际状态并定位根因，不重复盲试。
- 请求 Agent 调度或成本优化时，按任务难度选择模型与思考等级：机械工作用脚本，明确任务用轻量／均衡模型，复杂判断用 GPT-6；按阶段结果和失败原因持续调整，避免重复审计与无效并发。详见 [模型与持续调度](references/多智能体分工.md)。
- 质量检查通过后才生成飞书录入载荷；外部写入仍需单一写入者和回读确认。

验收范围是最终采用图及其对应原图。未使用图片的缺失、未审阅或历史译图失败不阻塞上架；所有采用图片仍需通过变体、语言和文件绑定检查。翻译计划输入需要显式 `selected_for_listing: true` 与 `publish_decision: include`，避免仅因含外语就批量生成。

用户明确要求的译图修复或翻译链路测试不能靠删图取消。真实异常按“观察、定位、修正、复测、继续”处理；已修复、已替代、可选排除、临时恢复和未解决分别报告。listing 视觉验收关注商品、英文和参数的正确性，合理缩放／重编码不自动等于图片不合格，文件哈希绑定另行核实。

## 安装

将本仓库克隆到 Codex Skills 目录：

```powershell
git clone https://github.com/yugao-tum/tiktok-listing-pipeline.git "$HOME/.codex/skills/tiktok-listing-pipeline"
```

重新打开 Codex 任务后即可使用 `$tiktok-listing-pipeline`。

## 使用边界

Skill 不保存密码、Cookie、验证码或账号令牌，也不会在未明确授权时直接发布商品或写入外部系统。

详细流程见 [SKILL.md](SKILL.md)。

## 维护与验证

实际对话模板见 [分阶段提示词](references/分阶段提示词.md)，可按原图审计、文案、翻译、译图复核和排序阶段单独使用。默认提示只处理用户指定产品或阶段，不自动扩成三个产品。

运行 `python -X utf8 tests/流水线回归测试.py` 可在临时目录验证正常交付、错误素材拦截、预览与正式载荷区分及批次重试。测试中的审计记录为合成数据，不代表真实图片经过 GPT 审计。

GitHub Actions 在推送及 Pull Request 时自动运行这组隔离测试。安装包可从 [Releases](https://github.com/yugao-tum/tiktok-listing-pipeline/releases) 下载；源码修改与发布包更新应对应同一提交。

升级后需重跑本地自动校验，并在实际文案复核后补齐 `质量检查报告.json` 的 `draft_sha256`；旧 QA 标签不能自动视为新版本已验证。详情中的内部 `notes` 不再输出给消费者，明确的消费者须知请使用 `consumer_notes`。预览模式使用 `preview_records`，不能直接交给写入者提交。
